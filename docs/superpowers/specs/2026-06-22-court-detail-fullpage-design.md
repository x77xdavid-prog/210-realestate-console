참고: madangs caview (사용자 제공 화면/PDF, 2025타경7974 양천 단독주택)

## 1. 배경 & 목표

현재 상세는 **모달**이라 담을 수 있는 정보가 제한적이다. madangs처럼 **새 탭 전용 상세 페이지**로 바꿔 당사자·임차인·제시외·주변입주·토지지구·시세까지 모두 담는다. 좌측 탭 네비(기본내역/현황정보/임차인/등기/시세분석/기타) + 우측 대법원 문서·분석 링크 레일.

## 2. 범위 — A+B+C (사용자 결정)

| 단계 | 내용 | 데이터 출처 | 상태 |
|---|---|---|---|
| **A** | 새 탭 전용 페이지 + 좌측 탭 + **이미 받는 데이터 전부** | 기존 `selectAuctnCsSrchRslt` 응답 | 🟢 데이터 보유, 렌더만 |
| **B** | **당사자 내역**(채무자/채권자/근저당) + **임차인 현황**(전입/확정/배당/대항력) | courtauction 송달내역/현황조사 엔드포인트 | 🟡 신규 — **구현 1단계 라이브 검증** |
| **C** | **주변 입주예정**(청약홈) + **시세분석**(국토부 실거래) | 청약홈 API(신규) · `market_price`(보유) | 🟡/🟢 |

### A에서 렌더할 "이미 받는데 안 쓰는" 필드 (응답에 키 존재)
- `gdsNotSugtBldLsstAll` — **제시외건물**(옥탑/주택 등, 구조·면적·감정가)
- `rgltLandLstAll` — **토지 지역지구/규제**(과밀억제·제2종일반주거 등)
- `bldSdtrDtlLstAll` — **건물상세**(사용승인일·층수·건축면적)
- `gdsRletStLtnoLstAll` — 소재지 지번 / `dstrtDemnInfo` — 배당요구종기
- `aeeWevlMnpntLst` 전체 10요항(현재 일부만) · 매각공고/물건비고
- (해당 데이터 없는 물건은 빈 리스트 → 섹션 자동 숨김)

## 3. UX / 구조

- **진입**: 보드 카드 클릭 → 현재 모달 대신(또는 모달의 "전체보기 →") **새 탭** `/detail.html?id=&cs=&court=&seq=` 열기.
- **레이아웃**: madangs형 — 상단 기본내역 바 + 사진/지도, 좌측 sticky 탭(기본내역·현황정보·임차인·등기·시세분석·기타), 우측 레일(대법원 문서 링크: 매각물건명세서·감정평가서·등기·건축물대장 → courtauction; 분석: 예상배당·수익률 등은 외부 링크/후순위).
- **기존 모달 유지**: 빠른 미리보기는 모달 그대로, "전체보기 →"로 새 탭 풀페이지. (모달/페이지 렌더 로직 공유.)
- 디자인은 기존 대시보드 톤 유지(§1 카드 결정과 동일 — 자체 스타일에 콘텐츠 주입).

## 4. 데이터/엔드포인트

- **신규 페이지**: `web/detail.html` + `web/detail.js`(+ 공유 렌더 모듈). `/api/listing/detail`(기존) 재사용, 응답에 A 추가 필드 포함하도록 `parse_detail` 확장(제시외/토지규제/건물상세/지번/배당종기/현황 전체).
- **B (구현 1단계 검증 후)**: courtauction 상세 페이지를 라이브로 구동해 당사자(송달내역)·임차인(현황조사) 데이터 호출 엔드포인트를 역공학 → `court_auction_detail`에 파서 추가, `/api/listing/detail` 또는 `/api/listing/parties`·`/api/listing/tenants`로 노출. (임차인이 현황조사서 PDF 파싱만 가능하면 별도 평가.)
- **C**: 주변입주 = 청약홈/한국부동산원 분양정보 API(data.go.kr) 신규 `cheongyak.py`; 시세분석 = 기존 `market_price` 연결.

## 5. 모델 확장

`AuctionDetail`에 추가: `presented_outside`(제시외 리스트), `land_regulations`(지역지구), `building_detail`(사용승인/층수), `parties`(당사자), `tenants`(임차인), `nearby_supply`(주변입주). 모두 기본 빈 튜플(데이터 없으면 섹션 숨김).

## 6. 단계별 진행 (구현 순서)

1. **A1**: `parse_detail` 확장 — 제시외/토지규제/건물상세/지번/배당종기/현황 전체 파싱 + 테스트(픽스처).
2. **A2**: `web/detail.html`+`detail.js` 새 탭 풀페이지(좌측 탭·우측 레일) — A 데이터 렌더. 보드/모달에서 "전체보기 →" 연결. 라이브 검증(데이터 있는 단독주택 케이스).
3. **B1(검증)**: courtauction 당사자/임차인 엔드포인트 라이브 역공학(detail 패턴). 가능성/형태 확정.
4. **B2**: 파서 + 엔드포인트 + 임차인/당사자 탭 렌더. 라이브 검증.
5. **C1**: 청약홈 API 연동(`cheongyak.py`) + 주변입주 탭. **C2**: 시세분석 탭(market_price 연결).
6. 통합·회귀·배포.

## 7. 리스크

- courtauction 당사자/임차인이 **현황조사서 PDF 파싱**만 가능하면 B 비용↑ → B1 검증에서 판단(구조화 엔드포인트 우선 탐색).
- courtauction fetch가 호출 컨텍스트(Referer/세션)에 민감 → 라이브 구동은 UI 세션 기반으로(역공학 시 실제 페이지 구동 캡처).
- 청약홈 API 키/쿼터 — data.go.kr 활용신청 필요.
- 사진/문서 원본은 §1과 동일: 저장 대신 courtauction 링크(저작권).

## 8. 성공 기준

- 카드 클릭 → 새 탭 풀페이지, 좌측 탭으로 기본내역/현황/제시외/토지지구/건물상세 탐색.
- 데이터 있는 물건에서 당사자·임차인(전입/확정/배당/대항력)·주변입주·시세가 표시.
- 데이터 없는 섹션은 자동 숨김. 기존 모달/보드/캘린더 회귀 없음.
